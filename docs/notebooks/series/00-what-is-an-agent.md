# 第 00 讲 · 什么是 Agent

> 系列导航见 [index](index.md)。本讲是全系列的起点，不要求任何前置知识，也不涉及任何 dsh 内容。

## 本讲回答什么问题

一句话：在写第一行代码之前，先搞懂 agent 到底是什么东西在转——答案是「模型 + 循环 + 工具」，三者缺一不可，而把它们捏合在一起的那层工程就是 harness。

## 逐块讲解（对照 [00-what-is-an-agent.html](00-what-is-an-agent.html) 图中编号）

**① 你交任务。** 你说的是目标（「找出最长的 README 并报告行数」），不是步骤。怎么拆解步骤是模型的事——这是 agent 和传统脚本的根本区别：脚本是你说清楚每一步，agent 是你说清楚要什么。

**② harness 带着上下文向模型提问。** 每次提问都打包三样东西：系统提示（你是谁、有哪些规矩）、对话历史（到目前为止发生过什么）、工具清单（每个工具的名字、用途、参数格式）。这里出现本系列第一个重要事实：**模型没有记忆**，它每次都是重新看一遍全部材料再作答；所谓「上下文」就是这次喂给它的全部材料。

**③ 模型给出两种回应之一。** 要么是一段最终回答（循环可以结束了），要么是一段结构化的工具调用指令——工具名加参数，形如「请调用 read_file，参数 path=README.md」。注意：这只是申请，不是执行。

**④ harness 真正执行工具。** 解析指令、检查权限、动手读文件或跑命令的是 harness 的确定性代码，模型全程没碰你的电脑。这是安全设计的支点：所有真实世界的动作都经过一层你可以审查、限制、拦截的代码。

**⑤ 结果写回上下文，回到 ②。** 工具的输出作为新消息追加进材料堆，再次请求模型。模型看到结果后可能继续申请下一个工具——于是 ②→⑤ 转起来，这就是 agent loop。

**⑥ 循环结束。** 当模型的回应里不再包含任何工具调用，harness 判定没有欠账了，把这段最终回答交还给你。什么时候停不是模型说了算，是 harness 数出来的：还有没执行的指令就继续转。

## 本讲新词

| 词 | 一句话定义 |
|---|---|
| LLM | 大语言模型，只做一件事：根据输入文本生成下一段文本 |
| 上下文（context） | 一次请求里喂给模型的全部材料；模型没有跨请求记忆 |
| 工具调用（tool call） | 模型输出的结构化申请：「请帮我执行某工具、参数如下」；执行者是 harness |
| agent loop | 提问 → 回应 → 执行 → 写回 → 再提问的循环，直到回应里没有工具调用 |
| harness | 把模型、循环、工具捏合成可用品的工程层；dsh 就是一个 harness |

## 带走的设计课

原则：**决策与执行分离**——模型只产出决策（文本或指令），一切真实世界动作由确定性代码执行。

为什么值得抄进你自己的系统：决策层可以随时整体替换（换模型不动 harness），执行层可以做严格的权限控制、审计和重试，两层各自演化互不拖累。

代价也要看清：模型对世界的全部认知来自 harness 喂的上下文，喂什么它信什么——上下文组装出错，模型就会自信地犯错。这个代价解释了 dsh 后面为什么对「日志与投影」近乎偏执（第 02 讲展开）。

## 动手任务：跑通你的第一个 agent

前置（一次性）：安装 Node ≥22.19 与 pnpm，然后在仓库根目录执行 `pnpm install && pnpm run build`（十几分钟，之后不必重复）。

主路径（有 DeepSeek API key）：在仓库根目录创建 `.env` 文件写入 `DEEPSEEK_API_KEY=sk-…`，然后：

```sh
pnpm dsh --profile headless "找出这个仓库里行数最多的 README.md，报告它的路径和行数"
```

这个任务必然触发工具调用——模型必须先找文件、再数行数，你会在终端看到它转完整个循环后打印最终答案。

验证标准：终端打印出包含文件路径和行数的回答；同时 `~/.dsh/` 目录下出现了新的会话数据（确切位置第 01 讲带你找）。

备选路径（暂时没有 key）：先读 [headless.snapshot.ts](../../../examples/headless-agent/tests/headless.snapshot.ts)，看一次真实会话在测试里被断言成什么样子；主路径等你拿到 key 再补做。
